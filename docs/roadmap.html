Roadmap

A clean path for study and repo growth

The objective is simple: keep the material readable in GitHub and in GitHub Pages, while allowing the repo to grow in a controlled way.

Suggested study order

  1. Start with the AI and ML foundations page.
  2. Move into LLM concepts and system design.
  3. Add examples, diagrams, and concise glossaries.
  4. Only then add deeper notes on tooling, RAG, and evaluation.

Publishing rule

Keep GitHub Pages content under docs/. That gives you a clean deployment boundary and avoids mixing generated artifacts with reading material.

Recommended file organization

  • docs/index.html: landing page
  • docs/foundations.html: foundational concepts
  • docs/llms.html: LLM systems and workflows
  • docs/topic-name.html: future topic pages
  • docs/assets/: shared CSS, diagrams, and light images

What not to commit

  • Large generated outputs
  • Local `node_modules` folders
  • Large binary exports unless they are essential primary artifacts
  • Scratch files from tooling workflows
If a file is large, generated, and not pleasant to review in a diff, it probably does not belong on the main docs branch.

Practical next expansions

  1. Add a glossary page and link it from the home page.
  2. Add simple diagrams as SVG or optimized PNG assets.
  3. Add short code examples or notebook summaries as HTML pages.
  4. Keep heavy artifacts in Releases or external storage, not in the docs branch.
